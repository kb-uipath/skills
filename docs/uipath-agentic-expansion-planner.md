# uipath-agentic-expansion-planner

Profile customer automation inventories and produce an evidence-backed, deployment-aware, on-brand, verified executive DOCX expansion brief.

## When To Use

Use this skill when a customer inventory must become a ranked Act 2 or agentic expansion portfolio, top recommendations, bounded POC candidates, and a customer-ready Word brief. The versioned JSON path is the auditable default. A Markdown-only brief can still be checked for structure, but it is not evidence-certified.

## Runtime And Dependencies

- Python 3.11 or newer.
- Standard library only for CSV/TSV profiling, JSON contracts, deterministic scoring, portfolio validation, Markdown rendering, and outcome rubrics.
- `openpyxl` for `.xlsx` or `.xlsm` inventory profiling.
- `python-docx` for DOCX rendering and verification. This dependency is required for the final artifact contract.
- Optional local Word/LibreOffice or Documents-skill renderer for visual page inspection.
- No credentials are required by the included scripts. They perform local file reads and writes only; public research is a separate read-only analyst step.

## Inputs

Versioned inputs:

- `inventory_profile.json`, schema `1.0`, generated by `inventory_profiler.py`. It contains stable `INV-*` IDs, normalized fields, and detected metrics derived from source sheet and row. Quantity shorthand such as `~24k` is normalized to `24000`.
- `evidence_ledger.json`, schema `1.0`. It records customer/deployment context, `INV-*` evidence, dated `SRC-*` public sources, `ASM-*` assumptions, and entitlement status.
- A portfolio draft, schema `1.0`, with `OPP-*` opportunities and criterion inputs. `score_portfolio.py` accepts the draft with derived `scores` and `rankings` omitted.

Human inputs still matter:

- Customer name, vertical, target audience, and account objective.
- Inventory file in CSV, TSV, XLSX, or XLSM format.
- Deployment model, data restrictions, human approval rules, and GenAI policy.
- Known UiPath entitlements, with evidence. Use `unknown` when unconfirmed.
- Current public strategy sources and their publication/access dates.

Unversioned JSON is rejected. Adding a version field to legacy data without migrating IDs and references is not valid.

## Outputs

- `inventory_profile.json` and `inventory_profile.md`.
- Validated `evidence_ledger.json` schema `1.0`.
- Deterministically scored `portfolio.json` schema `1.0`, scoring model `1.0`.
- Outcome rubric `1.2` values for specificity, decision utility, and pilot actionability. It deducts for missing quantified inventory signals, non-official public evidence, and unvalidated assumptions rather than awarding full credit for field presence.
- Deterministically rendered Markdown executive brief with criterion-level score rationale, explicit tie handling, and a default 3,500-word ceiling.
- Rendered `.docx` executive brief as the final user-facing artifact.
- Markdown content-validation and DOCX structural/brand-verification results.

## Prompt

```text
Use $uipath-agentic-expansion-planner on this inventory. Generate stable inventory IDs, build a v1 evidence ledger and portfolio, calculate and validate scores, render the executive Markdown, cross-check every claim, then render and verify the on-brand DOCX.
```

## Runnable Example

This read-only synthetic smoke path uses a one-opportunity sparse fixture, so the brief and DOCX checks lower only the count thresholds. Production briefs retain the default top 5/top 3 contract.

```bash
mkdir -p work/planner-demo/profile work/planner-demo outputs

python3 uipath-agentic-expansion-planner/scripts/inventory_profiler.py \
  --input uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/inventory.csv \
  --outdir work/planner-demo/profile

python3 uipath-agentic-expansion-planner/scripts/validate_portfolio.py \
  --evidence-ledger uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/evidence_ledger.json \
  --portfolio uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/portfolio.json \
  --inventory-profile work/planner-demo/profile/inventory_profile.json \
  --min-specificity 60 --min-decision-utility 85 --min-pilot-actionability 90

python3 uipath-agentic-expansion-planner/scripts/render_portfolio_markdown.py \
  --evidence-ledger uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/evidence_ledger.json \
  --portfolio uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/portfolio.json \
  --inventory-profile work/planner-demo/profile/inventory_profile.json \
  --output work/planner-demo/brief.md

python3 uipath-agentic-expansion-planner/scripts/validate_executive_brief.py \
  work/planner-demo/brief.md --min-recommendations 1 --min-pocs 1 \
  --evidence-ledger uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/evidence_ledger.json \
  --portfolio uipath-agentic-expansion-planner/tests/fixtures/golden/sparse/portfolio.json \
  --inventory-profile work/planner-demo/profile/inventory_profile.json \
  --max-source-age-days 365

python3 uipath-agentic-expansion-planner/scripts/render_executive_docx.py \
  work/planner-demo/brief.md outputs/planner-demo.docx --portrait

python3 uipath-agentic-expansion-planner/scripts/verify_executive_docx.py \
  outputs/planner-demo.docx --require-output-dir --require-brand-style \
  --min-proposal-headings 1 --min-poc-headings 1
```

For a new portfolio draft, calculate scores into a different path. The scorer refuses in-place overwrite:

```bash
python3 uipath-agentic-expansion-planner/scripts/score_portfolio.py \
  --evidence-ledger work/planner/evidence_ledger.json \
  --portfolio work/planner/portfolio_draft.json \
  --output work/planner/portfolio.json
```

## Failure Recovery

- Missing or unsupported `schema_version`: migrate using `references/data_contracts.md`; do not bypass the check.
- Inventory/profile ID mismatch: regenerate the profile, then deliberately remap affected `INV-*` references. Row insertion or sheet renaming changes IDs.
- Inventory/profile field mismatch: correct the ledger or regenerate the profile. Strict checks include description, status, department, owner, systems, source row, and detected metric values.
- Stale score or ranking: rerun `score_portfolio.py` into a new file and validate that file before replacement.
- Dangling or excluded evidence: correct the `INV-*`, `SRC-*`, or `ASM-*` reference. Do not downgrade the error to a warning.
- Value-math failure: fix the referenced input or use qualitative sizing. Arbitrary formulas are not accepted.
- Deployment or entitlement failure: change the claim to `requires_validation` or `likely_fit`, add evidence, or reject the opportunity.
- Placeholder pilot owner: name an accountable role or person. `TBD`, `unassigned`, and equivalent placeholders are rejected for active opportunities.
- Reserved or private official-source URL: replace it with the real HTTPS authoritative source and date, or mark a synthetic test source as non-official.
- Executive length failure: tighten narrative fields and remove repeated evidence; do not raise the word ceiling to preserve raw research notes.
- Markdown cross-check failure: fix the source JSON or Markdown, rerender, and rerun strict validation.
- Missing `openpyxl`: convert the workbook to CSV/TSV or install the dependency in an approved runtime.
- Missing `python-docx`: install it in an approved runtime. Markdown is an intermediate artifact, not a successful final deliverable.
- DOCX verification failure: fix Markdown or renderer inputs, rerender, and verify again. Do not deliver the failed file.

## Data Classification And Retention

- Treat inventory rows, owner names, operational metrics, case text, and customer constraints as customer-confidential unless the customer classifies them otherwise.
- Generated profiles, ledgers, portfolios, Markdown, DOCX files, and visual previews inherit the highest classification of their inputs.
- Keep only public source URLs in repository fixtures. Do not commit customer URLs, private SharePoint links, credentials, brand books, logos, or customer artifacts.
- Store working files only in approved local or customer-controlled locations. Apply least privilege and encrypt storage where policy requires it.
- Retain artifacts only for the customer-approved engagement or account-planning period. Delete temporary profiles, extracted files, rendered pages, and superseded drafts after transfer or when retention expires.
- Do not submit restricted data to public model endpoints. Deployment policy and data residency constraints are hard gates.

## Safety

- Treat sparse and noisy inventories as planning signals, not audited telemetry.
- Exclude archived, cancelled, retired, rejected, and duplicate rows from recommendation evidence.
- Require public source IDs and dates for strategy claims.
- Require official sources to use public HTTPS hosts; synthetic fixtures must not claim official status.
- Require assumption IDs for unverified value, feasibility, deployment, and entitlement reasoning.
- Keep deployment context as a hard constraint. `unknown` means validation is required. Active opportunities may address only the constraints that materially apply, but the active portfolio must collectively cover every ledger constraint.
- Claim `confirmed_entitlement` only when the ledger contains matching confirmed evidence; otherwise use `likely_fit`.
- Keep human approval for high-risk decisions and any system writes required by the ledger.
- Do not perform live external writes as part of analysis or validation.
- Do not store private brand assets or URLs in the repository.

## Known Limitations

- The scripts do not browse the web, verify live product availability, inspect a UiPath tenant, or confirm licensing. Analysts must supply current evidence.
- Stable inventory IDs depend on source sheet name and physical row number. Structural spreadsheet edits require regeneration and reference migration.
- Criterion inputs remain analyst judgments. Arithmetic and tie-breaking are deterministic and the rendered table exposes strongest and limiting criteria; opportunity quality still depends on evidence quality.
- Calculated value supports only `volume_minutes_rate_v1` and `hours_rate_v1`. Other cases must use qualitative sizing or a future contract version.
- Source freshness is enforced only when `--max-source-age-days` is provided.
- Markdown parsing supports the documented headings, fields, lists, and pipe tables; it is not a general Markdown engine.
- DOCX verification checks structure and brand tokens, not visual accessibility, factual correctness, or page-level layout. Visual inspection remains required when tooling is available.
- Golden fixtures are synthetic and do not prove fitness for every industry, regulation, or deployment topology.
